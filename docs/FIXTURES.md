# Fixtures: how pages become tests

No selector is ever guessed. Every adapter hook is written from a snapshot the owner captured, and every snapshot becomes a regression fixture.

## Capturing a page
- Open the application page and type nothing. Use Chrome's **Save page as… > Webpage, Single File** (`.mhtml`) and put the file in `fixtures/_incoming/`, which git ignores: a raw snapshot may hold personal data.
- For a state a Save dialog would close (an open dropdown, typeahead results), a **development** build's hotkeys save the live page, every frame included, through `pageCapture.saveAsMHTML`, which only development builds have:
  - Build one with `npx wxt build --mode development` and load `.output/chrome-mv3-dev` unpacked. The production builds (`npm run build`, `npm run build:edge`) and the e2e build hold neither the hotkeys, the permission nor the capture page; `scripts/check-build.mjs` fails one that does.
  - On the application page, press **Alt+Shift+S** to save it now, or **Alt+Shift+D** to save it in 3 seconds: press the keys, then open the dropdown again with the mouse before the time is up. If another extension has taken a key, choose another at `chrome://extensions/shortcuts`.
  - A tab opens just after the page, behind it, so the page keeps its focus and an open dropdown stays open. It saves the page and offers a link, **Save `<host>-<yyyymmdd-hhmmss>.mhtml`** (the page's host and the local time). Choose it and put the file in `fixtures/_incoming/`. Nothing is uploaded, and closing that tab lets go of the snapshot.
  - Not checked on a live page yet: whether pressing the keys itself closes a widget before the save. If it does, Alt+Shift+D is the way round it.
  - The result is the same kind of `.mhtml` as **Save page as**, so the converter below takes both.
- Workday: use a throwaway candidate account that holds only dummy data, never your own. Type the dummy data wherever a step requires it, and submit nothing.
- The owner's snapshots of 2026-11-06 were taken signed in, with real values typed, and with other extensions (Jobright, Simplify) active. Such a capture holds personal data: it stays outside the repository (never in `fixtures/`, never copied whole into a scratch file), it is converted only with the owner's redact file, and the capture of a step **before** it was filled is the one converted wherever one exists. A state that is an answer by nature (a file attached, an email code, Review) is kept only once every applicant value in it reads redacted.

## Converting it (`scripts/mhtml-to-fixture.mjs`)
`node scripts/mhtml-to-fixture.mjs fixtures/_incoming/x.mhtml --platform lever --case custom-questions [--redact redact.txt] [--out folder] [--folder name]`

- `--platform` is one of `FIXTURE_PLATFORMS`: greenhouse, lever, ashby, workday, workable, icims, taleo, successfactors, oracle, smartrecruiters, and the fifteen new ATSs (jobvite, jazzhr, bamboohr, rippling, breezy, careerplug, pinpoint, paycor, hibob, ultipro, dayforce, paylocity, dice, clearcompany, adp: `NEW_ATS_PLATFORMS`). It decides how the case's frames are normalised and which platform rules run. `--case` is lower-case words joined by hyphens; `--out` defaults to `fixtures/`.
- `--folder <name>` writes the case into `<out>/<name>/` and names it so in its header, the platform still deciding the frames' rules: `--platform greenhouse --folder sites` for a company page around a Greenhouse frame. A `sites` case keeps only the style rules its elements match, as iCIMS's do.
- The redact file holds one string per line (your name, your address, an account id); blank lines and lines starting with `#` are skipped, and an entry shorter than 3 characters is refused. A string that looks like a phone number matches its digits whatever the punctuation. Keep the file outside the repository: it lists your own data. Add each multi-word entry's joined spellings too (underscore, hyphen, dot, none): a resume named after a person rarely keeps the space, and an entry with one never matched such a file name.

What it does, in order:
1. **Renders the capture.** Playwright's bundled Chromium (headless, JavaScript off, the page's CSP bypassed) opens the `.mhtml` itself, so Chromium's own MHTML loader resolves its parts and frames. Every network request is aborted: conversion never reaches the network. The converter also reads the archive's MIME parts (quoted-printable, base64), for the stylesheet text and image bytes it inlines. Each closed shadow root's host is marked through the DevTools protocol (`markClosedShadowHosts`, `data-fixture-closed-root`), for its stand-in (step 6).
2. **Takes away what is not the site's page, before anything is measured** (the snapshot build of 2026-11-06, every platform), so the visibility check compares the site's own page:
   - other extensions' UI (`INJECTED_UI`: Jobright's `<plasmo-csui id="jobright-helper-plugin">`, Swooped's `#swooped-extension-root`; `stripInjectedInPage`);
   - on a platform that does not keep shadow roots, an overlay drawn in one: a shadow host that is a child of `<body>` and whose open shadow tree holds no form control, form, frame or nested shadow root (an accessibility widget, a cookie banner, a route announcer);
   - per-load tokens (`PER_LOAD_PARAMS`: Greenhouse's embed `validityToken=`, reCAPTCHA's challenge frame `bft=`, HubSpot's visitor ids `hsutk=`, `__hstc=`, `__hssc=`, `__hsfp=`), whose value becomes `REDACTED` wherever it stands: the page, a frame's address, the header and the route map alike, so a frame's `src` still finds its route;
   - the choices a page mirrors (`clearChoicesInPage`), beside the `checked` and `selected` step 6 drops: `aria-checked="true"` and `aria-pressed="true"` become `"false"`, `data-checked="true"` becomes `"false"` and a bare `data-checked` goes; a chosen phone country loses its flag's region (`iti__<cc>` in a react-select's chosen value), and intl-tel-input's country button its title, aria-label, flag region and dial code (`REDACTED`); and every mark `CHOSEN_MARKS` names loses its chosen classes and attributes, and its `aria-selected="true"` becomes `"false"`. `CHOSEN_MARKS` holds Ant Design's chosen radios, boxes and list options (Dayforce), react-widgets' `rw-state-selected` (Paylocity), HiBob's drawn radios' `selected`, and, since the security fix of 2026-11-06 (S2, S3, S10), the chosen marks of every platform keyed by markup: a CSS module's `_checked_`, `_selected_` and `_active_` classes whatever the hash (Ashby), MUI's `Mui-checked`, `Mui-selected` and `Mui-focusVisible`, a BEM `--checked`, `--selected`, `--is-selected`, `--is-focused`, `--is-checked`, `--active` or `--is-active` modifier on an option or a choice (its role, or a class naming an option, a choice, a radio or a checkbox: Oracle's `__button--checked`, react-select's `__option--is-selected`, BambooHR's `fab-MenuOption--active`), `aria-selected="true"` on an option, a calendar's day or a tree's item (Workday's own empty "Select One" aside), and SmartRecruiters' `<spl-dropdown-item selected>`. A tab's, a menu's, a link's or a pager's own modifiers are no answer and stay;
   - every animation and transition is finished (an endless one paused at its start) before each visibility measurement, on both sides of the conversion (`measureInPage`): Pinpoint's fade-in and Oracle's drop zones measured as a person sees them.
3. **Inlines** every stylesheet as a `<style>` in the place of its `<link>`, so the cascade order is kept, with `@import` inlined and every `url()` a `data:` URI. Images become `data:` URIs too. An image over 100 KiB becomes a grey SVG of the same pixel size, so its box (all that visibility needs) is unchanged. A reference the archive lacks (web fonts, mostly) becomes `data:,`, so a fixture never makes a request.
4. **Removes** scripts, `noscript`, `on*` attributes, `javascript:` URLs, `<base>`, every `meta http-equiv` (refresh and CSP included), `object`, `embed` and `srcdoc`, and every `<link>` but the stylesheets and `rel=canonical`. Every form gets `action="/__submitted"` and `method="post"`, and every `formaction` becomes `/__submitted`, so any submission is recorded as a failure.
5. **Frames.** Each frame on an ATS host is converted the same way into `<case>.frame-N.html`: the hosts in `src/shared/hosts.ts`, Oracle's (commercial and government cloud) by the candidate path, and the new ATSs' by their candidate paths (`NEW_ATS_HOSTS`: UltiPro's same-host `RelyingPartyIframe` is converted, ClearCompany's `/blank/page` is not). Every other frame (a CAPTCHA, Google's API proxy, LinkedIn's widget) keeps its `src` but is answered by one empty stand-in page, `<case>.third-party-frame.html`: the extension never runs there. A frame with no web address is left blank. **Each frame is converted before the frame that holds it** (the reverse of the order they were found in): a parent's conversion points its frames' `src` at their real addresses, which navigates them away from the document measured (or nowhere, once a token in the address is `REDACTED`), so a frame converted after its parent was another document, and a frame inside it detached ("Frame was detached": iCIMS's IForm frames its form a level deeper; a company page's Greenhouse embed carries a `validityToken`).
6. **Redacts:**
   - typed values are cleared: text-like input values, textareas, `contenteditable`, and a widget's mirror of what was typed (react-select's `data-value`);
   - `checked` and `selected` are dropped;
   - hidden-input values become `REDACTED`, and so does the text of listbox and combobox triggers (`[role=combobox]` and `[aria-haspopup=listbox]` elements that are not native controls) and of chips and chosen values (`single-value`, `multi-value`, `chip` classes, Workday's `selectedItem`); option lists keep their text;
   - emails, phone numbers (written with `+` or separators, 10 to 15 digits) and every redact-file string become `REDACTED` in text, comments and attributes. Phone numbers are looked for only in text and in attributes that carry words (`value`, `placeholder`, `title`, `alt`, `aria-label`, `content`, `data-*`, `tel:` links), never in SVG geometry, styles or ids. A `tel:` or `sms:` link's number becomes `REDACTED` whatever its spelling, percent-encoded too, once its address holds 7 digits or more (ABC Legal's `tel:+1(NNN)%20NNN-NNNN`).
   - **The applicant's own text the redact file may not hold** (`redactApplicantTextInPage`, every platform, each place keyed by the markup that showed it and naming its snapshot in a comment): an upload's file name (`FILE_NAME_PLACES`: Greenhouse's `.file-upload__filename`, Ashby's file item, Workable's drop zone `[data-id="filename"]`, Workday's `file-upload-item-name`, and the new ATSs' file rows and chips), its text and title, and that name wherever else the frame repeats it, as written and percent-encoded (Workday's "Delete <name>", "Category for <name>"); the controls beside a file that name and link to it (`FILE_LINK_PLACES`: Workable's view and delete, their aria-label "<their data-action> REDACTED", the link to the file's signed storage address `#`); a resume's entries shown as text (`ENTRY_SUMMARY_PLACES`, `ENTRY_SUMMARY_CONTROLS`: Workable's saved Education and Experience entries, every `dd`, their Edit and Delete labelled "<title> REDACTED"); chosen answers drawn outside a native control (`CHOSEN_PLACES`: BambooHR's Fabric toggles and date button, Rippling's announced choice, Ant's shown selection, react-widgets' input and Paylocity's chips, ADP's phone country, HiBob's chosen country, UltiPro's skill chips, Dice's React Aria shown option and its `title`), their aria-label, title and alt words included, a list's own options kept; the account's and the profile's own text (`PROFILE_PLACES`: a welcome line, an account menu, an e-signature's date stamp, read-only summaries of what was entered or parsed: ADP's, Dice's, UltiPro's, Dayforce's, Paylocity's, HiBob's, ClearCompany's upload date); a custom element's `value` and `default-value` (an option's own element excepted), `data-date-value` and `data-gtm-form-interact-*`; the option words of a searchable Ant select's open list (it holds only what the search matched); UltiPro's Race row drawn open (its open or closed state told the Hispanic-origin answer); ClearCompany's uploaded file's server id (`tr.file-row[data-id]`). Every file name found is also looked for in the final check, as a found email is. The header counts the places (`redacted.applicantText`).
   - **Per platform** (`PLATFORM_REDACTIONS`, by `--platform`), what the generic passes miss there:
     - Workday (`redactWorkdayInPage`, before the transformation, counts under `redacted.workday`): the Review step's value cells; any other read-only summary (an element that is no control, named by a `label[for]`); the header's account menu; an upload's name wherever repeated, and any word ending in a document's extension in text and labelling attributes (never in an address); a dropdown's chosen words, option id and aria-label; a prompt's pill words, its labels and its announced "1 item selected, <answer>"; an open list's chosen option; an exclusive group's disabled boxes enabled again; a date's displayed digits, spin-button values and help text, back to Workday's own MM/DD/YYYY placeholders.
     - iCIMS (`icimsRedactInPage`, after it, iCIMS frames only, text nodes alone so every element stays): the header's name (`.iCIMS_userMenuName`), a file field's current file name (`.iCIMS_CurrentFile > span`), and iCIMS's dropdowns: a dropdown's hidden select (`icimsdropdown-enabled="1"`) holds only the chosen option, so its options' text and values go; `icimsdropdown-selected` and `aria-activedescendant` on every select, the anchor's `aria-activedescendant`, a result's `aria-selected` and `result-focus`/`result-selected`, a searched list's results and the value a trigger shows (`.dropdown-select .dropdown-text`).
     - Oracle and SmartRecruiters (`redactPlatformInPage`, after it, counts added to the frame's): Oracle's work and education timeline's tiles (`.beautiful-timeline-item__info`: title, employer or school, the hidden dates) and its year axis, an attached file's name (`button.attachment-upload-button__download`: text, title, aria-label), the submission checklist's greeting by first name, its answer pills unchosen; SmartRecruiters' form elements' `value` attributes (`spl-input`, `spl-select`, `spl-phone-field`, ..., an option's own kept), a select's chosen value on its trigger (`[slot="triggerPrefix"]`: the phone's country, flag and dial code), and the phone field's 245 country flags, each a grey SVG of its own size (2.7 MB of a 3.6 MB page).
   - **Another extension's parameters** (`INJECTED_PARAMS`: Jobright's `jr_id`, Simplify's `utm_source=Simplify`, a `name=value` entry dropped with that value alone) leave every address and each frame's written text by one rule (`stripInjectedParams`; `stripJrId` is that rule for `jr_id` alone): the page's, its frames', the header's and the route map's, plain, as `&amp;` entities or percent-encoded once or twice. The header counts `jr_id`'s removals (`removed.jrIds`).
   - **Sign-in tokens** (`SIGN_IN_TOKEN_SOURCES`, every platform: an OpenID `id_token`, a JWT whose base64 claims name the account, and a silent-callback page's one-time `code=`; UltiPro's hidden `RelyingPartyIframe?id_token=<JWT>`) become `REDACTED` by one rule (`redactSignInTokens`) in every address and each frame's written text, plain, after `&amp;` or percent-encoded once or twice. Being base64, neither reads as an email or a listed string. The header counts them (`redacted.signInTokens`).
   - Ashby (`--platform ashby`): its per-load ids are normalised (`normaliseAshby`), so a fixture is the same whenever its page was captured: each form's render id, which prefixes every `data-field-entry-id` and every radio's and checkbox's `id`, `name` and `for`, becomes `00000000-0000-4000-8000-00000000000N` in the order the page first names it, and the per-load CSP nonce of `meta[name=csp-nonce]` becomes `REDACTED`. The header counts both (`normalised`).
   - Workable (`--platform workable`): the ids its React draws afresh on every render are normalised (`normaliseWorkable`): every 16-character id an element carries, alone or with Workable's prefix or suffix (a radio's or checkbox's own id, `wrapper_<id>`, `<id>_label`, `input_<id>`, `checkbox_label_<id>`, `radio_label_<id>`, `svg_<id>`, `input_files_input_<id>`, `description_input_<id>`, `<id>_dropdown`, an open list's `<id>_<option>`), becomes `wk00000000000000N` in the order the page first names it, wherever it stands (the `for`, `aria-labelledby`, `aria-describedby`, `aria-controls` and `aria-activedescendant` naming it with it). An open shadow root's own `<style>`s are left whole. The header counts the rules kept and dropped (`pruned`), and the reload's visibility check holds the result. Workday's sheets are kept whole: its tests stage one capture's view inside another's page (the choice in the posting, the landing in the Sign In page), whose rules the page itself would not keep.

For the platforms of `SHADOW_ROOT_PLATFORMS` (SmartRecruiters, whose one-click application is drawn in them, and the fifteen new ATSs: ADP's, Dice's and UltiPro's pages) every query and walk of the passes above, the visibility check and the rescan reach into each open shadow root, nested ones too (`deepenInPage`), and the frame is written with them as declarative shadow roots (`serializeDeepInPage`, `<template shadowrootmode="open">`), which the HTML parser attaches again when the fixture loads, in the DOM tests' frame and the e2e harness alike; the header counts them (`shadowRoots`). 7. **Checks, before anything is written.** It reloads the result as the e2e harness serves it (at its real address from the route map, JavaScript on) and refuses to write anything, printing the reasons, when:
   - a body element is shown or hidden differently from the capture's own rendering (checkVisibility and a box of at least 4 by 4 pixels, element for element);
   - the page requests anything the route map does not answer (the browser's own `/favicon.ico` request aside, as in e2e);
   - the reloaded page still holds an email, a phone number, a redact-file string, a value it redacted or a file name the page showed;
   - the written files (the route map included) still hold a redact-file string, a redacted email or a redacted file name, as written, entity-decoded or percent-decoded (inlined stylesheets and base64 payloads are page assets and not searched);
   - the written files hold anything `tokenNeedles()` finds (core pass Z1, item 38: one list for the conversion and the sweep test): `jr_id` anywhere, another extension's parameter or UI, a per-load token whose value is not `REDACTED` and nothing after it (a token's percent-encoded padding left behind is refused), a sign-in token, or a JWT under any name;
   - the written files hold a chosen mark (`chosenMarksIn`, the security fix's S2): a CSS module's, MUI's or a `CHOSEN_MARKS` class, a BEM chosen modifier on an option or a choice, `aria-selected="true"` on an option, a day or a tree item (Workday's empty "Select One" aside), `aria-checked` or `aria-pressed` "true", `data-checked` "true" or bare, a custom list item or option that says `selected`, or a radio or box input that says `checked`;
   - a page of a platform outside `SHADOW_ROOT_PLATFORMS` has a shadow root step 2 did not take away;
   - an ATS frame it links to did not render from the capture.
8. **Writes** `fixtures/<platform>/<case>.html` (or `fixtures/<folder>/`), its frame files and `<case>.routes.json`, replacing an earlier conversion of the same case. Each HTML file opens with a header comment holding JSON: the fixture's name, its source URL, the capture date (the MHTML `Date` header), the Chrome version that converted it, and counts of what was redacted, removed and inlined (never values). The keys the snapshot build added are written only when non-zero, so earlier fixtures' headers read as before: `redacted.applicantText`, `redacted.signInTokens`, `redacted.workday`, `removed.jrIds`, `shadowRoots`, `closedShadowRoots`, `injected: { injected, shadowOverlays, injectedParams }` and `cleared: { choices }`. The same capture and the same Chromium give byte-identical files.
- It prints each file's size, the counts, how many elements' visibility it compared, and the long random-looking strings left (query tokens, ids) so you can add any personal one to the redact file and convert again. That list is taken before some normalisations run, so it can name a value the written file no longer holds (a `jr_id`'s hex value, ClearCompany's view counters): search the file before acting on one. Read it for each new case before committing; the places the owner's snapshots left were page tokens (iframe `src` of third-party frames, link query strings, `meta content`, `data-sitekey`, the platforms' own data attributes and binding paths), judged one by one in each case's notes below.
- Its test, `test/mhtml-to-fixture.test.ts`, converts a synthetic capture built in Chrome's own layout and one saved from a live page through Chrome's serializer (CDP `Page.captureSnapshot`), checks every inlining, removal and redaction, and checks that each probe element is shown or hidden as before. Each rule the snapshot build added has a block that fails with the rule undone (the per-platform redactions, a synthetic three-level IForm capture, the shadow roots, the closed-root stand-in, the token needles, the chosen marks). Two sweeps read every committed fixture (`committedFixtureFiles`, which since v4 skips the git-ignored `fixtures/_incoming/` and `fixtures/.generated/`: raw captures and generated pages a checkout may hold): one with `tokenNeedles()` over every page, frame and route map (about 500 files), one with `chosenMarksIn` over every page, which only `CHOSEN_STATE_FIXTURES` may fail: the hand-written synthetic pages and trap 10, the developer's read-only public captures of 2026-11-01/02 (Ashby and Workable: nothing typed but test strings, an open tab, a list's first result highlighted, intl-tel-input's default country, the captures' test choices) and v3 Phase 8's Netflix pages (OneTrust's cookie switch, on by default). Every fixture converted from the owner's snapshots holds none.

What a capture cannot hold, so neither can its fixture:
- Chrome's serializer saves every `<style>` element as a `cid:` stylesheet placed before the page's `<link>` stylesheets, and drops `adoptedStyleSheets`. Where the cascade order decides, a capture can show what the live page hid, or the reverse. The converter keeps the capture's order; its own check proves only that conversion changed nothing. A shadow tree styled by adopted sheets is unstyled in the capture and the fixture alike: what the live page hides there by style (a closed dropdown's list, a drop zone's file input) shows, and what it draws there (UltiPro's `ukg-field` boxes) is not drawn.
- Chrome already drops scripts, `noscript`, event-handler attributes, `javascript:` URLs and hidden inputs from what it saves. The converter removes them anyway, for any other source. So a capture holds no JSON-LD and no React props: whether a company page's live script names a JobPosting, or what a widget's React state holds, is never in a fixture.
- Web fonts are not archived, so text falls back to local fonts, in the capture as in the fixture. Line breaks may differ from the live page; visibility does not.
- A closed shadow root is kept only as its host's box.
- Runtime behaviour: what a page does after a press, an open list's events, how a date part takes typed digits. The owner's snapshots show states; each adapter's "still unknown" list (docs/OWNER-QUESTIONS.md §12) names what no capture shows.

## Expectations (`<case>.expect.json`)
Each case has a `<case>.expect.json`, written by hand from the page itself and never from a scanner, which the scanner test compares against. Its header repeats the fixture, the source URL and the capture date. `fields` lists every form control on the page in document order, a radio or checkbox group as one entry, hidden ones included. Each entry has:
- `label`: the label as shown, whitespace collapsed, without the markers the scanner strips: a trailing `*` or `✱` (which `required` records), "(required)", "(optional)" and a trailing colon. It is `""` for a control nothing labels. A label past 300 characters is cut there, as every field's label is (`TEXT_CAP_LABEL`).
- `kind`: one of `FIELD_KINDS` (`src/core/enums.ts`), for what the control is: a react-select is a `combobox` (or `multiselect`, or `typeahead-remote` when its options come from a search), even before Phase 4 handles it.
- `required`: whether the page marks it required (the `required` attribute, `aria-required`, a required upload group, or a visible marker).
- `section`: the text of the nearest visible heading above the control, the one just above the form included (Greenhouse's "Apply for this job"); inside a hidden part, that part's own heading; `""` outside the form.
- `fillable`, and `reason` when it is false:
  - `widget-phase-4`: a script-driven custom widget no helper acts on (one its adapter declares and the widget helpers act on, as Greenhouse's react-selects since 2026-11-01, is `fillable: true`, of the kind the adapter declares);
  - `not-user-visible`: hidden by the page and tied to no visible control, so the scanner never makes it a field (a widget's required shim, a reveal that has not happened, a CAPTCHA's response field);
  - `disabled-or-readonly` (Phase 5): a field the page shows but has disabled or made read-only, which the fillers never write (the wizard's End date while "I currently work here" is ticked).
- `control`: a CSS selector for the control, or for every input of a group. Since core pass Z2 (2026-11-06) it may step into an open shadow root with `" >>> "` (`selectComposed` in `src/adapters/test/expectations.testkit.ts`): the first step anywhere in the document, each next one anywhere inside the open shadow root of the element before it (UltiPro's start date, `ukg-date-input-text >>> input[data-automation="ukg-date-input-text-month"]`; SmartRecruiters' `spl-input#first-name-input >>> input`, which its own test's `compareDeep` reads with the same rules).
- `options`, for choice kinds: the number of radios or checkboxes in the group, or of `<option>` elements in a select (a "Select..." placeholder included), or `"lazy"` for a widget whose options exist only once it is opened.
- `note`, where the reading needed explaining: which adapter hook a control needs (a group label no element ties, an upload widget), how a hidden control is revealed.

A file input hidden behind a visible upload button is `fillable: true`: the spec allows it once the adapter declares the widget, and the note names the hook.

- A field with no heading inside its form root is in the scanner's default section: its `section` is `"main"` (the heading of an account page often sits above the form root: iCIMS's gate, Taleo's login, Oracle's gate).

**Hooks (v3 Phases 6 and 7b).** A posting or an account page holds few questions, and what an adapter must read there is its hooks, so those cases' expectations carry a `hooks` entry beside `fields` (`src/adapters/test/hooks.testkit.ts` compares it), written by hand from the page, each selector naming one element (a selector ending in ` @<n>` names the n-th, from 0, of a page's copies: two Apply buttons, top and bottom):
- `detect`: the form root, or `null` (a posting); `authState`: the page the adapter names (`sign-in`, `create-account`, `email-gate`, `email-code`, `entry-choice`, `forgot-password`) or `null`;
- `postingText` and `entryControl`: the element, or `null`;
- `signInForm`: for its `wall`, each slot's selector (`email`, `password`, `confirm`, `terms` a list, `button`) and `scriptSubmits` when the page's script sends the form; `null` when the page shows none for any wall; `signInPrelude`: `{wall, control}` or `null`;
- `neverPress`: selectors every element of which the adapter names never to press; `pressable`: selectors none of whose elements it names so (Sign-in Auto's own controls: since core pass Z1, ADP's guest Continue and UltiPro's Create account, a sign-in container's buttons).
A posting's `fields` is `[]` (no form root). A frame whose fields cannot be held yet holds its `hooks` alone and says why in a top-level `note` (iCIMS's `aon-gate-consent.frame-1`, and the two IForms' own form frames, `edgewater-self-id-veteran.frame-2` and `nyu-self-id-disability.frame-2`, whose radios are labelled by bare text). A wrapper page that is never a root has no expectation file; its adapter's test holds that it is never read as one. Where the scanner reads a page differently from the page itself, the adapter's DOM test names each difference and why in its `KNOWN` list (or `findings.testkit.ts` for the cases the expectations testkit reads), and fails once the difference goes, so the list is emptied then. The snapshot build's core passes emptied most of them (below); what is left is named there.

**Steps (Workday's application, the owner's snapshots of 2026-11-06).** Each Workday step fixture's expectations also hold a `steps` entry, read by `src/adapters/workday/workday-steps.browser.test.ts`: `signature` (`heading`, `progress` and `anchors`, as `stepSignature` gives them), `final` (`isFinalStep`: `final`, `not-final` or `unknown`), `next` and `submit` (the selectors of the step's Next and Submit, or `null`), `widgets` (each declared widget's `control`, `kind` and whether it reads `answered`), and `repeatables` (each kind's `blocks` and its Add button's words).

**States (synthetic pages that react, Phase 3).** A page whose own script reveals, removes or reloads fields also lists, in `states`, what it holds after given answers. `fields` above is the page as it loads; each state is reached from a fresh load and has:
- `name`, and `variant`: the value of a `data-variant` attribute put on `<html>` before the page loads (the async-options page's variants), or `null`;
- `steps`, in order, each acting on the page as a filler would, with untrusted events: `{ "choose": selector, "value": v }` sets a select's value and dispatches `input` and `change` (bubbling); `{ "click": selector }` calls `click()` on a radio, a checkbox or a button (the wizard's Next and Add buttons);
- `until`: a CSS selector the page must match before the scan (a list that loads late), or `null` when the page reacts at once;
- `fields`: every control in the page then, as above. A control the state removed is not listed; one it hid is listed as `not-user-visible`.
`fixture`, `source` and `fields` keep the shape the adapters' expectations testkit reads (`src/adapters/test/expectations.testkit.ts`), so a state is compared by passing its `fields` in their place. `captured` says the page was never captured.

**Steps (a multi-step page, Phase 5).** The wizard's expectations also hold a `wizard` entry, at the top for the page as it loads and in each state: what its e2e-only test adapter answers there. `shown` is the step shown (1 to 4); `heading`, `progress`, `urlPart` and `anchor` are the parts of its step signature, as `stepSignature` gives them (the one anchor in `anchors`); `final` is `isFinalStep`; `next` is the selector of the step's Next button, or `null` on the last step; `repeatables` maps each repeatable kind the shown step holds to its number of blocks. `src/adapters/test/wizard.browser.test.ts` holds the adapter to them.

## Serving fixtures
In e2e runs every request goes through `e2e/routes.ts`: a URL in the route map is answered from its fixture, the mock TailorIT and the extension's own files pass through, a form post to `/__submitted` is recorded (any hit fails the test), and everything else is aborted and recorded. Fixtures are served at their real ATS addresses: Phase 0 proved that Chromium injects the content script into such routed pages.
- A converted case's `<case>.routes.json` is that map for its page and its frames (URL without fragment to repo-relative file), in the shape `installRoutes` takes.
- A fixture's iframes keep their captured addresses. A harness without routing (a fixture loaded into a `srcdoc` iframe) must blank them first, or they reach the network.
