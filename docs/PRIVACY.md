# Privacy: what the extension keeps, where, and why it asks for each permission

TailorIT Autofill fills job applications from a profile the person keeps in their own TailorIT. It submits an application only on the person's own click on Submit application in its panel, with Submit set to Auto under Modes (v3 Phase 4), or, with Run auto-apply turned on, for a job the person queued in TailorIT (v3 Phase 5); it never logs a field value, keeps the resume and the cover letter only for the seconds it takes to attach them (or to show the resume's preview in the side panel), and holds a job-site password (Sign-in Auto, v3 Phase 5) only for the one sign-in it is typed into. This file is the source for the store listing's privacy answers and permission justifications.

## The page-world bridge

To choose an option in a page's React dropdown as the page's own code does (docs/SPEC-AMENDMENTS.md §12), the extension runs one small script in the page's own world on the ATS hosts, beside the content script, which runs apart from the page. It holds nothing: no profile, no answer, no token, no setting, no state but the one listener it waits on, and it reaches no part of the extension (no messaging, no storage, no browser API, no network).
- **The page sees everything it is told.** The page's own scripts fully control the world the bridge runs in: they can read every request, change how the bridge behaves and answer in its place. So nothing is sent there that the page should not read.
- **What it is told:** for each dropdown answer, which option to choose (its label, as the extension read it from the page), whether the dropdown takes several answers, what kind of request it is, and a random id. The label reveals the answer the fill is choosing exactly as the filled form will show it to the page, a moment earlier. Asked about a field, the bridge answers that field's type and path as the page's own code names them (two short strings), never a value.
- **The field question on Ashby:** Ashby's adapter asks the bridge what each of the page's dropdowns is (its `react.field` request: the request and its random id, nothing of the person's), to tell a Location search from a list. The page's scripts can see that request whenever the extension reads the form, a dry run's reading included, and so learn that the extension is reading it; it carries no answer, and nothing is written.
- **What it never gets:** any profile value, typed answer or anything else of the person's. The content script writes those as before, and a remote search's typed query still goes into the page's text box as before; the bridge only chooses an option the page lists.
- **What the page can do with it:** read its requests, send it requests of its own (which can only make it choose one of the page's own options on that page), and tell, from the moment it loads, that the extension is installed, since the bridge acknowledges a request. Its answers are never trusted: the content script reads the page back itself.
- **Where it is there at all** (the v3 Phase 6/7b review, and its round 2): it is read from the frame's own address before any script of the page runs (`src/adapters/address.ts` `bridgeInstallsAt`).
  - On the hosts that serve only public job postings, any page: `job-boards.greenhouse.io`, `boards.greenhouse.io`, `jobs.lever.co`, `jobs.eu.lever.co`, `jobs.ashbyhq.com`, `jobs.smartrecruiters.com` (once the extension runs there), `apply.workable.com` and a Workday tenant's own `<tenant>.myworkdayjobs.com` (with or without `wd<n>`). A board there can route to a posting without loading a new page, and the posting's dropdowns still need the bridge.
  - On the domains that also hold an employer's own pages, only at a posting or its application form, by the platform's own address parser: iCIMS (`*.icims.com`, which also serves internal-mobility portals), Taleo (`*.taleo.net`), SuccessFactors (`*.successfactors.com`, `*.successfactors.eu`, which also serve employees' performance pages), Oracle Cloud (`*.oraclecloud.com`) and Workday's shared `myworkdaysite.com`. Anywhere else there, nothing of the extension is in the page's world, not even a listener that stays quiet, which a page could otherwise find by moving its own address to one that looks like a posting.
- **Nothing announces the extension:** the content script (in its own world) has no WXT content-script context, which used to dispatch an event naming the extension's id on every page it ran on (round 2, E1). It listens for events named after the extension's id (a page forging WXT's, logged as such) only where the bridge installs, decided once from the address the document was loaded at, so on an employer's own pages on an ATS domain no listener of ours runs that a page could time to learn the extension is there, not even after the page moves its own address to a posting's (round 3, X1, and round 4, Y1). It tells the extension's worker nothing (no `frame/hello`) on a page whose address shows no posting, until the page's own navigation shows one.

## Forms that save as they are filled (Ashby)

Ashby's application form saves every answer to Ashby's own server about half a second after it is written, and again when the field is left, before anything is submitted (the live capture of 2026-11-01: each change is a `POST` to Ashby's `ApiSetFormValue`). A file put into an upload question is uploaded to Ashby the moment it goes in (`ApiCreateFileUploadHandle`, then the file). Its SMS consent is sent to Ashby the moment one of its two answers is chosen. The page does this for a person's typing too; the extension neither causes nor stops it.
- **So a fill reaches Ashby at once, before Submit.** Every answer the extension writes on an Ashby form is in Ashby's hands within about a second, whether or not the person then submits: the profile's answers, and, under the owner's policy (the AI fills everything, its drafts accepted by default), the AI's answers, its drafts and its best guesses ("AI guess") too.
- **Files at once.** The resume, and a cover letter (the AI's letter included, when TailorIT's AI wrote it), are uploaded to Ashby's server the moment the extension puts them into the form, before Submit. The extension then waits for Ashby to show the file uploaded (its name with its Delete file button), at most 10 seconds; a file Ashby says failed to upload, or never shows uploaded, is flagged for the person, never verified.
- **Nothing to undo there.** The extension's final check can put a field back as it was once the run ends (its guard's revert), but Ashby has already saved what was written; Ashby saves the reverted value the same way. Nothing is ever submitted, and the person can still change or clear an answer before they submit, which Ashby saves the same way.
- **Drafts held back on request.** With the setting that keeps AI drafts for the person's confirmation on, an AI draft is not written into an Ashby form at all until the person confirms it in the panel (Confirm draft): until then it stays in the extension's memory, and Ashby sees nothing of it. A field the person typed into meanwhile is theirs, and the draft is dropped.
- **A month sets this year first.** Choosing an Education block's month makes Ashby choose this year in its year list too (and save it), until the extension chooses the year a moment later; a run stopped between the two leaves this year saved.
- **A dry run writes nothing,** so nothing of the person's reaches Ashby: no field is typed into, nothing is chosen or clicked, no file is put in. (The bridge's field question above is a reading, and is asked in a dry run too.)
- **Never pressed:** Ashby's "Autofill from resume" (which uploads a resume to Ashby's server and rewrites the form from it), its Upload File and Delete file buttons, and an Education block's Delete. Submit only on the person's click on Submit application in the panel, or with Submit on Auto (v3 Phase 4).
- **The SMS consent follows the Consent boxes mode** (v3 Phase 3). Under All agreements, the default, its Yes ("given") is chosen like every agreement on the form, and choosing it sends the consent to Ashby at once (`ApiSubmitCandidateTextingConsent`), before Submit. Under Required only it is optional and not pre-approved by default, so it is left for the person and nothing is sent.

## Workable keeps a draft in the browser (v3 Phase 7a)

- **The Address is prefilled from the visitor's IP** ("<city>, <country>"): the page's guess, which the profile's location replaces, flagged for a look (`prefill-conflict`).
- **An answer's layout (API 4):** a number box or a date box asked of the AI names the layout its answer must have (a number, a sum, a date as the box writes it), so TailorIT's AI answers one value of it or none; the layout is page structure, never a value.
- **Never pressed:** Workable's "Import resume from" (which uploads a resume to Workable and rewrites the form from it), each section's Clear, the upload buttons and a file's remove control, a saved entry's Edit and Delete, an editor's Cancel and the cookie banner; Submit only on the person's click in the panel or with Submit on Auto (the agent does not take Workable jobs yet). ## The auto-apply agent (v3 Phase 5)

The owner's decision (docs/SPEC-AMENDMENTS.md §12 Decision 9): with Options › Auto-apply › "Run auto-apply" on (off by default, turned on only after the person confirms, once, that applications go out unattended with AI-guessed answers), the extension applies by itself to the jobs the person queued in TailorIT.
- **What it asks TailorIT:** its next job (GET /agent/next, scope `agent:run`), at most every 30 seconds while it is on and a browser window of the person's is open, waiting a minute, then five, while the queue is empty or TailorIT cannot be reached. TailorIT answers the job's id, title, company, its application form's address and the resume to attach, and binds the job to this browser's connection until it reports.
- **What it does:** opens that address (only a canonical application address on Greenhouse's job-boards.greenhouse.io, Lever, Ashby or Workable's apply.workable.com, since TailorIT's API 4, that the extension fills; anything else is reported failed, unsupported site, and never opened) in a new window of its own, which Chrome is asked to open unfocused; fills only the form of that job's own application (another posting's page in its tab, or a page naming none, ends the job unfilled) exactly as Autofill does, with every rule above (the profile, the AI help as the settings allow, the agreement boxes, the cover letter and the resume TailorIT named for the job); presses Next and Submit by itself, Submit once per job (once it was pressed, a form shown again in another document gets Submit on Manual and no run, and the job waits for the site's confirmation); presses a posting page's own Apply (or Ashby's Application tab) when the page shows the posting first; signs in only as the person's Sign-in mode says. At a posting that forbids AI with "Ask me each time" chosen, nobody is there to answer, so it fills from the profile only and its skip rule decides.
- **What it tells TailorIT:** how the job went (POST /agent/:id/result: submitted, skipped, needs you or failed, a reason from a closed list, and how many answers were AI guesses, a count). A submitted job is marked Applied by TailorIT with that result (the extension does not also call POST /applied for it). Never a value, a question or an answer.
- **When it stops and leaves a job for the person:** a check that the person is human, a bot check, an email code, a sign-in it cannot do, a required field still empty, a posting that forbids AI (with those two skip rules on, the default), a legal answer that was the AI's guess (with that rule on, off by default), errors the page still shows after one retry, a closed posting, a page that does not load, ten minutes without progress (25 in all), the person closing its tab, Stop, Run auto-apply turned off, the disclosure changing, the connection losing `agent:run`, or the connection changing or going (which also turns Run auto-apply off and asks for the person's confirmation again). It then lets go of its tab (its run cancelled, the person's own settings back) and closes that tab only, never a window and never a tab already gone. The job stays listed in TailorIT's Auto-apply page for the person. A result TailorIT cannot take yet is kept and sent again (a submitted one for every answer but 404 and 400), and the status says "a result not yet told TailorIT" until it is.
- **A window in the background:** Chrome slows the timers of a page in a window behind others (intensive throttling, after about five minutes hidden), which can stretch the fill's waits for the AI's answers. A run still at work counts as progress, so only ten minutes with neither a new report nor a run at work, or 25 minutes in all, ends the job (timed out).
- **Who can start it:** only the person, in the options page; its commands come only from the extension's worker, with its own token, after its own look at TailorIT. No page, frame or message from a page (TailorIT's own pages included, which may message the extension for pairing alone) can start it, choose its job, make it submit or learn the password.
- **The `alarms` permission** wakes the worker every 30 seconds while it is on, or while a result waits to be told (the browser stops an idle worker after about 30 seconds); otherwise no alarm is set.

## Agreement boxes (the Consent boxes mode)

The owner's decision of 2026-11-01 (docs/SPEC-AMENDMENTS.md §12): every agreement box is ticked, like Jobright, unless the person chooses otherwise under Options › Modes.
- **All agreements (the default):** every consent the extension recognises is ticked or chosen: a privacy notice, terms, an accuracy statement, keeping the application on file and future jobs, a background check, news and job alerts, text messages, and a signature (the profile's full name is typed). ## What reaches an AI model

Only through the person's own TailorIT, which runs the Claude CLI, and only when the AI settings allow it:
- the visible text of a question and its visible options, to pick among them or to say what a question asks;
- for a pick, the profile's value for that question (a school, a degree, a field of study, a language, a referral source, or a custom answer). A value that names a sensitive topic or a sum is never sent, except that a school's, a degree's or a field of study's own name is checked for a sum only, since "Gender Studies" or "United States Military Academy" is just its name;
- for a draft (on by default since the owner's amendments, docs/SPEC-AMENDMENTS.md), the visible question, the posting's visible text on the form's own page (none for a form embedded in another site's page, and none in a dry run, which asks for no draft), the job's title and company, the words hidden page text asked AI tools to write (so TailorIT refuses a draft holding one), and which resume to draw on. TailorIT adds facts from the resume itself. A draft is written into the form, marked as the AI's in the review (nothing is drawn on the page; it waits for the person's confirmation only while the "Wait for me to confirm each draft" setting is on). No draft is asked for a box in a self-identification, legal, pay or consent context: under such a heading, revealed by such a question, following one up ("If yes, please explain"), or in a section of such questions only;
- for an AI answer (on by default since the owner's amendments), the same as a draft's, for a question nothing else settled: its visible label, hint, section and, for a choice, its visible options' clean labels by their places. TailorIT reads the facts itself from the resume and the profile's non-sensitive part (work history, education, languages, skills, job preferences), never the sensitive part, contact details, the name, the address or saved answers. An answer with nothing to go on is written marked "AI guess". The same screens keep every self-identification and consent question, and every box in such a context, from it, and so does a question about another person (an emergency contact, a referee, a manager or a spouse), an identifier (a number, an ID, a licence, a passport, a birth date), a postal address, a marketing or contact consent, an "I did not use AI" statement or a question whether AI wrote the application;
- for the legal, pay and attention-check questions the profile does not answer (the owner's decision of 2026-11-01, docs/SPEC-AMENDMENTS.md §11: the AI answers mode All under Options › Modes, the default since v3 Phase 3 (before it, the setting "Let the AI answer legal, pay and attention-check questions your profile doesn't answer"), and only while AI answers are on): a work authorization, sponsorship (now, in the future or both), visa, citizenship or residence status, security clearance, export control, age or 18-or-over, criminal history (convictions, arrests, charges) or pay question, or an attention check ("select PURPLE to show you read this"), as any AI answer: its visible label, hint, section and visible options, in TailorIT's `all` scope. Never the person's own answer: a question the profile answers is filled from it and never asked, and a question is asked only when the profile holds no answer (never while this browser may not read the sensitive part, where the person may hold one). TailorIT gives the most likely answer from the resume and the profile's non-sensitive part, marked "AI guess" unless a fact settles it. An EEO option ("Woman", "Asian"), a self-identification or consent topic, an identity number, another person and an "I did not use AI" statement are never sent in this scope either, by the extension and again by TailorIT, and hidden page text never is: a question whose words only an aria-label or hidden text carries is never asked;
- for Edit with AI (the person's click on the button in a text box), the box's question and what it holds now (page text, which may be the person's own words), with the draft's context, so TailorIT rewrites it. A box whose text holds words hidden page text asked AI tools to write, names a sensitive topic or a sum, holds a self-identification answer or a decline ("Prefer not to say") on a line of its own, or holds an email address, a phone number, a link or a postal address, is never sent (the extension's screen, as TailorIT screens the same text). Since v3 Phase 3b the person may type what to change in its box ("Tell me what to add, change or improve", at most 750 characters), which goes with it as the question's instruction, screened the same way (an instruction naming a sensitive topic or stating a sensitive answer, a contact detail or a postal address is never sent, and the box says so). That box sits on the job page, in the extension's own closed part of it: what is typed there is typed on the page, so the page's own scripts can learn it as they learn any typing there. The extension stops the box's events from reaching the page's ordinary listeners, but a script that listens for every event on the window or the document in the capture phase still hears, besides each key (keydown and keyup), the text each keystroke enters (beforeinput and input carry it), anything pasted into the box (paste) and what an input method composes (composition events). A person who would rather not have the page see an instruction can use the side panel's custom question instead. The words are never kept;

- for a cover letter (Phase G; since v3 Phase 3b a cover-letter text box as well as an upload), when a form has a cover-letter upload and the person has no letter for the job, or when they choose Write it now on the job card: the job's title and company (TailorIT's, or the page title's when TailorIT lacks the job), the posting's visible text on the form's own page (none for a form inside another site's page, never TailorIT's stored copy), the words hidden page text asked AI tools to write (TailorIT keeps no letter holding one), and which resume to draw on. TailorIT's cover-letter AI writes it from that resume into the person's Cover Letters. Only while AI-written answers (the "Draft open answers" setting) are on, never in a dry run (the card offers no Write it now there), never when the form's page cannot be read, and never on a posting that says AI is not allowed in profile-only mode or a form that states "I did not use AI", where only a letter the person wrote or edited is attached. Every ask first checks whether the person has a letter, and only a fill or Write it now that may have one written, finding none, sends the posting text. Asking whether the person has a letter (every ask's first step, a dry run, the card's row, a profile-only fill, and the upload after the extension's worker restarted) sends the job (TailorIT's, or the page title's company and title when TailorIT lacks it) and the resume only: no posting text, no canaries, and nothing is written;

- for a custom question the person types in the side panel (v2), their question, the posting's visible text on the form's own page (none for a form inside another site's page), the job's title and company, the words hidden page text asked AI tools to write, and which resume to draw on (the one the job card attaches, or the one chosen with Change); TailorIT adds facts from that resume. A question about self-identification, work authorization, sponsorship, pay or consent, or one that checks the person read the form, is never sent, by the extension and again by TailorIT.

Edit with AI and the custom question run only when the person asks (their click on Edit with AI, or Get answer), and only while AI-written answers (the "Draft open answers" setting) are on: with it off, Edit with AI is not offered, the custom question box is disabled with the reason, and the worker refuses either if asked. A custom question still works on a posting that says AI is not allowed, since the person asked; the side panel shows that posting's notice above it, and with the answer.

Never: self-identification (EEO) answers, work authorization, sponsorship, criminal record, pay, consent, contact details, hidden page text, or TailorIT's stored copy of a posting. Questions that look like self-identification or consent questions, by their words, their hint, their section's heading or their options, are screened out before classification, a draft or an answer, by the extension and again by TailorIT; so are legal, criminal-history, pay and attention-check questions, but for the AI answer above while its setting is on.

When a posting says AI-assisted applications are not allowed, or its form asks the person to confirm they did not use AI, the default ("Fill from my profile only", the owner's amendments) sends nothing at all to the AI for that run: no pick, classification, draft or answer, and Edit with AI is not offered. A run that learns it only on a later pass gives up what it was still waiting for from the AI and writes none of it, and the worker asks the AI nothing more for that run. The other choices are "Ask me each time" (the policy card) and "Use AI anyway".

- the `pageCapture` permission;
- two keyboard commands: Alt+Shift+S saves the page in the active tab, every frame included, and Alt+Shift+D does so after 3 seconds;
- the page that saves the snapshot. It offers the file as a link to save, so the snapshot never leaves the computer, and it lets go of it when its tab closes.

`scripts/check-build.mjs` fails any build it checks (Chrome, Edge and the e2e build, all production mode) that holds the permission, a `commands` key, the capture page or the hotkeys' code.

## First-run disclosure (shown before Connect)

The options page shows this above Connect whenever the extension is not connected. Its words live in `src/shared/copy.ts` (`COPY.options.connection`), and `src/shared/copy.test.ts` keeps this copy the same. It is a draft for the owner's review: it names the AI help as on, because picking from lists and working out unusual questions are on by default.

> **Before you connect**
>
> TailorIT Autofill fills job applications on Greenhouse, Lever, Ashby, Workable, Workday, iCIMS, Taleo, SuccessFactors and Oracle Recruiting Cloud from the profile you keep in your own TailorIT (on the last five it knows the sign-in and posting pages so far; their application forms get its standard rules). It reads the job pages you open on those sites, fills what it is sure of and lists the rest for you to review. It submits an application only when you choose Submit application in its side panel, set Submit to Auto under Modes, or turn on Run auto-apply; once the site confirms it, it tells your TailorIT tracker the job is Applied. With Run auto-apply on, it takes the jobs you queue in TailorIT one at a time, opens each in a window of its own while this browser is open, fills it, and submits it without you watching, AI guesses included, unless the rules under Modes leave it for you; it tells your TailorIT how each one went, never what it filled in. With Sign-in on Auto (only if you allowed it when connecting), it reads the job-site email and password you saved in TailorIT for the site you are on, types them into that site's own sign-in or new-account form (ticking the new account's terms box), and keeps them in memory only for that sign-in; where a site asks for your email alone first and then emails you a code (Oracle Recruiting Cloud), it types the email, ticks that step's terms box and goes on, and the code is yours; checks that you are human, password resets and email codes stay yours. Unless you choose Required only under Modes, it ticks every agreement box a form shows, news, job alerts and text messages included, except a binding clause the form does not require (an arbitration agreement, say) and a box saying you did not use AI, which it ticks only when the fill used no AI. Some sites (Ashby) send a text message consent to the employer the moment it is ticked. Some sites keep what is filled before you submit: Ashby saves answers and files as they go in; Workable uploads an attached file at once and keeps the answers in this browser for an hour.
>
> When an application page or a job posting on those sites loads, and again while its side panel shows one, it tells your TailorIT which job page you are on, so TailorIT can name the job, your tracker entry for it and your match before you open the panel; it does so again when you choose Autofill or Dry run, add the job or change the resume. TailorIT does not keep the page's address unless you add the job, or mark it Applied after you submit. Its side panel can show and change your autofill information in your TailorIT, and preview the resume it attaches. When you choose Autofill, it fetches your profile from TailorIT, and your resume and your cover letter for the job when the form asks for them. It keeps them in memory only, never on disk: your profile until five minutes after its last use, and the files only for the seconds it takes to attach them. This browser keeps your settings, where you put or hid its button on each site, notes on each application's progress and, until you close the browser, a sealed record of the list options you submitted, which it can match again but never read: never your answers.
>
> Its AI help sends the visible text of a question and its visible options, with the answer from your profile it is trying to match, to your TailorIT, which asks Claude. Picking from lists, working out unusual questions, drafting open answers (a cover letter too, when the form asks for one and you have none for the job) and answering the questions your profile does not are on unless you turn them off below; drafts, cover letters and answers also give Claude the posting's visible text, and TailorIT gives it your resume and profile to write from. An answer with nothing to go on is marked "AI guess". On a posting that says AI is not allowed, nothing goes to the AI unless you choose otherwise below, or ask a question of your own in the side panel. That question, and Edit with AI in a text box, go to the AI only when you ask, and only while AI-written answers (Draft open answers, below) are on. Unless you choose Profile only for AI answers under Modes, questions about work authorization, sponsorship, a visa, a clearance, age, criminal history or pay that your profile does not answer, and attention checks, get the AI's best guess too, from the question and its options alone. Your self-identification, work authorization, sponsorship, criminal record, pay and consent answers never go to the AI. The extension talks only to your TailorIT.
>
> Choosing Connect means you agree to this.
