# The dry run on live postings

The owner chose to try the extension on live postings through a **dry run**. A dry run plans every field and shows the report a fill would give, and writes nothing: no field is typed into, nothing is clicked, nothing is submitted. It still reads TailorIT (the profile, the lookup) and, when its switches are on, asks TailorIT's AI about fields the rules could not settle.

During Phases 2-6 TailorIT's autofill backend was built in a worktree (`F:\Develop\TailorIT-wt-autofill`, branch `autofill`), and the dry run used a build of its own (`npm run build:worktree`) against that worktree's scratch servers on 3300. That branch is now merged into the owner's checkout, `F:\Develop\TailorIT` (branch `v1.2`), so the dry run uses the ordinary production build against the owner's own TailorIT on `http://localhost:3100`.

## What is built
- `npm run build` builds the production extension into `.output/chrome-mv3`. Its TailorIT is `http://localhost:3100`: its `host_permissions` and `externally_connectable` name that origin, and so does `__TAILORIT_ORIGIN__` in its bundles.
- Every build has the same manifest `key`, so the same extension id (`flmloalhjldmcihejnmkndbcnhaacmng`). TailorIT accepts that id when `AUTOFILL_EXTENSION_IDS` is unset.
- `npm run check:build` checks the build against the manifest the plan allows. Building starts no server and calls none.

## Steps
1. **Build the extension** in `F:\Develop\TailorIT-autofill`: `npm run build`.
2. **Load it:** in Chrome (144 or later) open `chrome://extensions` and turn on Developer mode. Every build of this extension shares one id, so remove any other build of it first (the earlier dry run loaded `.output-worktree\chrome-mv3`). Then choose **Load unpacked** with `F:\Develop\TailorIT-autofill\.output\chrome-mv3`.
3. **Start your TailorIT** when Claude says so: `npm run dev` in `F:\Develop\TailorIT`, then open `http://localhost:3100`. The first start after the merge applies the autofill migrations to your own data.
4. **Pair it:** open the extension's options page (right-click its toolbar button, Options). Read the disclosure and choose **Connect**. Then, on `http://localhost:3100/settings/autofill`, Extension tab, choose **Connect the extension**, with "Let this browser read work authorization and self-identification answers" ticked or not as you prefer. If the hand-off does not complete, type the code the page shows into the options page. The pairing and profile from the earlier dry run were in the worktree's scratch data, so they do not carry over.
5. **Fill Settings › Autofill** at `http://localhost:3100/settings/autofill`: the Profile tab (by hand, or "Fill from my resume" and then check the notes), with the resume to attach. Then work through **Answer these once** at the top of that tab: work authorization and sponsorship for each country, the criminal-record question and the self-identification answers. These are never guessed: one left empty stays blank on every form (an empty self-identification answer picks the form's "Decline to self-identify"). Save.
6. **Dry run two live postings per platform:** Greenhouse, Lever, Ashby and Workday. On each application page open the side panel (the toolbar button): the job card shows the posting as TailorIT knows it (or **Add this job to TailorIT**), your match and the resume it attaches. Choose **Dry run** first. Read the report: each row's status, where its value would come from (Profile, Saved, Rule, AI pick, AI answer), its matcher stage and reason. A dry run asks the AI no answers or drafts, so questions only the AI would answer show as "would be filled". When a dry run reads right, choose **Autofill** on the same posting: every answer is filled, AI-written ones marked "AI" and best guesses "AI guess" on the page and in the panel; Edit with AI rewrites a text answer. Nothing is ever submitted: check the form and press Submit (or Next) yourself.
   - Ashby has its own adapter (v3 Phase 2, from the live capture of 2026-11-01): its Yes/No buttons, radio and checkbox questions, dropdowns, Location and School searches, dates and Education block are filled and read back. Ashby draws its form a few seconds after the page loads, so the launcher appears then. **Ashby saves every answer to its own server about half a second after it is written** (docs/PRIVACY.md, "Forms that save as they are filled"): a dry run writes nothing, so nothing is saved, but an Autofill's answers reach Ashby before you submit, as your own typing would: the profile's answers, the AI's answers, drafts and "AI guess" answers alike, and the resume and any cover letter (the AI's letter included) are uploaded the moment they go in. The extension's final check can only put a field back after Ashby has saved it. To keep AI drafts off Ashby until you have read them, turn on the setting that keeps drafts for your confirmation: on Ashby a draft is then not written at all until you press Confirm draft. A resume Ashby says failed to upload shows as flagged ("The file was attached, but the site says it failed to upload"): attach it again yourself. Its SMS consent is saved the moment it is chosen: under Consent boxes: All agreements (Modes, the default) the extension chooses Yes like every agreement, which sends it to Ashby at once; choose Required only to leave it to you.
   - Expect Workday pages to be read by the generic adapter only (its adapter arrives with its snapshots), and multi-step Workday applications to show their first step only.
   - The AI is the real Claude CLI your TailorIT is configured with: `AI_CLI_BIN` in its `.env`, with the model `AI_CLI_MODEL` names unless `AI_MODEL_AUTOFILL_PICK` or `AI_MODEL_AUTOFILL_CLASSIFY` overrides it. The questions the extension asks (visible page text, and a tiebreak's intended value from the profile) go to Claude. TailorIT deletes each such task an hour after it finishes. A dry run asks for no drafts or answers. The options page's AI switches turn each AI step off (tiebreak, classification, answers, AI-written answers); "When a posting forbids AI" chooses between filling from the profile only (the default), asking you, or using AI anyway.
   - A cover-letter upload (Phase G): a dry run only asks TailorIT whether you have a letter for the job (nothing is written, by you or by its AI, and no page text is sent). Its row says "Your cover letter for this job was attached from TailorIT" when you have one, or that a fill would have TailorIT's AI write one. The job card in the side panel shows the same under the resume ("Your letter for this job", or "Written by AI when the form asks for one"), with no **Write it now** while the tab's run is a dry run: nothing is written into your TailorIT's Cover Letters until you fill for real (or press Write it now outside a dry run).
7. **Afterwards:** remove the unpacked extension, or disconnect it on its options page.

## What to send back
For each posting: the platform, whether the launcher appeared, the report's counts (verified, flagged, blocked, skipped), and any row whose label, value source or reason looks wrong, by its label. A screenshot of the side panel is enough; a snapshot (docs/FIXTURES.md, "Capturing a page") helps where a widget was not read.
